# 원격 연결 중 물리 화면 가리기

호스트 Settings → General → **Hide this Mac’s screens during remote use**를 켜면, 연결된 기기에서 보는 화면을 유지하면서 물리 모니터에 검은 창을 표시한다. 기본값은 꺼짐이고 호스트에만 저장한다. 모바일 및 Mac 뷰어에서 이 설정을 변경하는 프로토콜은 추가하지 않는다.

- 유효한 원격 세션이 하나라도 있는 동안 덮개를 유지한다. 여러 기기 중 하나만 연결을 끊어도 나머지가 있으면 유지한다.
- 덮개는 잠금 해제 후 생성하는 대신 연결 중 미리 유지한다. 잠금 화면에서 직접 비밀번호를 입력해 해제하면 원격 앱 조작을 계속할 수 있다.
- 마지막 유효 세션이 끝나거나 설정을 끄면 Mac 잠금을 요청한다. 명시적인 잠금 상태를 확인한 뒤 1초 동안 덮개를 더 유지하고, 여전히 잠긴 상태인지 확인한 다음 덮개를 제거한다. 확인하지 못하면 덮개를 유지하고 General과 로그에 오류를 표시한다.
- 정상 종료와 SIGTERM도 잠금을 확인한 뒤 종료한다. 실패하면 종료를 취소한다. 두 번째 종료 신호, 강제 종료, 충돌, WindowServer 장애까지 보호하지는 못한다.
- 로컬 **Control–Option–Command–B**는 현재 연결 세션 동안 화면을 드러낸다. Accessibility 권한이 있어야 다른 앱을 사용하는 중에도 단축키를 감지할 수 있다. 로컬에서 드러냈어도 마지막 연결 종료 시 잠금은 요청한다. 모든 연결이 끊겼다가 새로 접속하면 다시 가린다.
- Sill 자체 가상 디스플레이는 덮지 않는다. Desktop 캡처는 Sill 앱의 창을 제외한다. 덮개가 활성화됐는데 제외 대상을 확인할 수 없으면 Desktop 캡처를 시작하지 않는다.

커서는 물리 화면에 보일 수 있다. 검은 창은 패널의 전원을 끄지 않는다. 일반 창보다 높은 시스템 UI나 macOS의 전환 애니메이션 전체를 제어하는 보안 기능은 아니므로 모든 상황에서 화면 내용의 무노출을 보장하지 않는다.

잠금 요청은 `login.framework`의 `SACLockScreenImmediate`를 런타임에 확인해 사용한다. 잠금 확인은 기존 `SessionLock`과 같은 세션 사전의 `CGSSessionScreenIsLocked`를 명시적으로 확인한다. 잠금·해제 알림과 이 키 및 함수는 비공개 구현에 의존하므로 macOS 업데이트 후 실제 검증이 필요하다. 함수가 없거나 상태를 확인하지 못할 때 덮개를 자동 제거하지 않는다.

## 검증 기록

2026-10-31, 이 Mac의 물리 화면 1개와 정식 모바일 Sill로 실험한 결과, 잠금 해제 시 육안으로 작업 내용이 보이지 않았고 원격 숫자 영상과 버튼 클릭이 정상 동작했다. 물리 화면에는 커서만 보였다. 정식 구현도 같은 날 모바일에서 영상·버튼 정상 및 마지막 연결 종료 시 자동 잠금을 사용자 확인했다. 다만 재시험에서 잠금 전환 중 작업 창의 fade-out 흔적이 보인다고 확인돼 무노출 판정을 취소했다. 20:56:53.993 연결 종료, 20:56:54.129 잠금 확인 후 덮개 제거 로그가 남았고, 별도 관찰기도 잠금 상태 전환을 확인했다.

다중 모니터, 전체 화면 Space, 빠른 재접속 중 잠금 경쟁, API 실패 및 강제 종료는 실제 기기 검증을 완료하지 않았다. 다음 절의 화면 복구와 뷰어 표시는 후속 변경에서 추가했다.

### 잠금 전환 보완

잠금 상태 확인 직후(연결 종료 약 0.12초 후) 덮개를 제거하던 구현에서 작업 창의 fade-out 흔적이 육안으로 보였다. 잠금 알림의 즉시 제거를 없애고, 정상 종료를 포함한 모든 자동 제거가 공통 잠금 확인의 1초 대기와 상태 재확인을 거치도록 변경했다. 대기 중 재접속하면 제거 작업을 취소한다. 변경 후 사용자는 fade-out 자체는 남지만 작업 창이 아닌 검은 덮개가 fade-out되어 목적에 부합한다고 확인했다. 이 대기는 합성 완료를 보장하는 API가 아닌 경험적 완화이며, 다른 환경의 무노출을 보장하지 않는다.

## 꺼진 화면에서 접속하기

유효한 원격 세션이 접속할 때 물리 화면이 꺼져 있으면 깨우기를 요청하고, 디스플레이가 돌아온 뒤 목록을 갱신해 마지막 선택을 재시작한다. 연결 중 화면 꺼짐/켜짐 알림과 캡처 오류 -3815에서도 같은 복구를 시도한다. 연결이 모두 끝나면 복구를 취소하며, 반복적으로 화면을 끄는 외부 앱과 무한히 경쟁하지 않도록 1분에 3회로 제한한다. 복구용 화면 목록 조회에는 기존 3초 제한을 적용한다.

2026-10-31 실제 시험에서 화면을 끈 뒤 새로 접속하자, 모바일 트랙패드를 움직이지 않아도 잠금 화면 영상이 나타났다고 사용자가 확인했다. 로그에도 21:10:54 활성 디스플레이 없음·잠금 → 21:11:01 물리 디스플레이 켜짐·잠금 유지 → 21:11:02 Desktop 캡처 재시작이 남았다. 사용자가 물리 화면을 직접 보지는 못했으므로 물리 화면 상태는 API 관찰에 근거한 결과다.

Mac 뷰어는 새 호스트가 전송하는 optional `HostSettingsState.screenLocked`가 true일 때 **Mac Locked**와 **Show Lock Screen**을 표시한다. 잠긴 앱 영상이 움직여도 입력은 잠금 화면에 전달됨을 안내한다. 예전 정식 호스트가 이 필드를 보내지 않으면 상태를 추정해 표시하지 않는다. iOS 클라이언트는 새 필드를 무시하므로 기존 정식 앱을 그대로 사용한다. 뷰어는 빌드 검증했으며, 별도 Mac 간 잠금 표시 전환의 실제 검증은 아직 하지 않았다.
