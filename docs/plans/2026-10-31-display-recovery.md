# 디스플레이 깨우기·캡처 복구와 뷰어 잠금 표시

목표: 꺼진 화면에 접속하거나 연결 중 화면이 꺼졌을 때, 유효 세션이 있으면 화면을 깨우고 준비된 디스플레이 목록으로 마지막 선택을 다시 캡처한다. Mac 뷰어에는 잠김 상태와 Desktop에서 해제하라는 안내를 표시한다.

1. 기존 DisplayActivity의 깨우기를 재사용한다. StreamCoordinator에서 화면 꺼짐/켜짐 알림 및 -3815 캡처 중단을 처리한다. 하나의 복구 Task에서 화면 준비를 기다리고 최신 선택을 재시도하며, 연결 종료 시 취소한다. 반복적인 BLEUnlock 꺼짐과 무한히 싸우지 않도록 시도 횟수를 제한한다.
2. SessionLock에서 표시용 잠금 상태를 읽는다. 기존 HostSettingsState에 optional screenLocked를 추가한다. 처음 접속 시 전송하고 연결 중 기존 통계 틱에 상태를 반영해 변경 시 다시 보낸다. 구버전은 필드가 없어도 디코딩되며 모바일은 모르는 필드를 무시한다.
3. Mac 뷰어에 잠금 표시와 Desktop 선택 안내를 추가한다. 잠긴 앱 영상이 보여도 입력은 잠금 화면으로 향한다는 사실을 표시한다. 알 수 없는 상태를 잠금 해제로 표시하지 않는다.
4. 호스트·CLI·뷰어 빌드와 기존 프로토콜 검사로 확인한다. 새 영구 테스트 코드는 생략한다. 실제 디스플레이 꺼짐 후 새 접속을 모바일로 확인한다. 로컬 Mac 뷰어의 잠금 UI는 가능한 경우 연결해 확인한다.
5. 한국어 Conventional Commit으로 커밋한다. 원본 설치 앱 교체와 원격 푸시는 별도 요청 없이 하지 않는다.

## 검증 결과

- 정식 모바일 앱으로 디스플레이 꺼짐·잠금 상태에서 새로 접속한 결과, 트랙패드 입력 없이 잠금 화면 영상이 나타났다고 사용자가 확인했다. API 관찰에서도 물리 디스플레이가 다시 켜졌고 잠금 상태가 유지됐다.
- 호스트/CLI/뷰어 릴리즈 빌드, 두 앱 패키징·서명, 기존 away-quality/설정 프로토콜 검사 및 diff 검사를 통과했다.
- 리뷰에서 복구 경로의 화면 목록 조회가 무기한 기다릴 수 있음을 발견해, 그 경로에만 기존 3초 제한을 재사용했다. 최종 리뷰에서 추가 중요 결함은 보고되지 않았다.
- Mac 뷰어는 기존 설치 경로에 갱신해 실행했다. 권한과 페어링이 유지되는 별도 테스트 호스트에도 최종 바이너리를 적용해 정상 대기를 확인했다. 원본 /Applications/Sill.app은 교체하지 않았다.
- Mac 간 잠금 상태 배지 전환, 다중 모니터, 외부 잠금 앱 반복 충돌 및 오류 주입은 실기기 검증하지 않았다. 이전 정식 호스트는 optional 잠금 상태를 보내지 않아 배지를 표시하지 않는다.
